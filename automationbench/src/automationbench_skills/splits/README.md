# Frozen splits

- `train.txt` — 450 tasks (75 per scored domain). Beaker (or any optimizer) may
  run these freely and mine trajectories/assertions to write skills.
- `test.txt` — 150 tasks (25 per scored domain). Held-out for final evaluation
  only. No validation split: model selection happens on train.
- `simple.txt` — the optional 200-task `simple` domain, train-only material;
  it is excluded from all scored metrics.

Tasks are keyed by `task_name` (`<domain>.<name>`), the benchmark's only
globally-unique stable id (`example_id` collides across domains).

## Procedure

Generated by `make_splits.py` from the pinned `automation-bench` commit:
per scored domain, tasks are grouped into families (first underscore token of
the name, e.g. `docusign_contract_send` → `docusign`), each family's test quota
is set by largest-remainder allocation of 25 seats proportional to family size,
and members are drawn with a fixed seed (`random.Random(0)`). This stratifies
test across task families so held-out tasks are near-neighbors of train tasks
rather than whole unseen families.

## Regeneration

```bash
uv run python -m automationbench_skills.data.make_splits
```

Deterministic for a given dependency pin. Do not regenerate casually: any
change to these files invalidates comparisons across runs (and, once skills
have been optimized on train, moving tasks between splits is leakage).

## Leakage policy

- Never read `test.txt` tasks (prompts, assertions, trajectories) while
  authoring or optimizing skills.
- Skills may encode anything learned from train/simple tasks or general
  product knowledge, but must not reference specific test tasks.
- Report test metrics only for configurations frozen before touching test.
