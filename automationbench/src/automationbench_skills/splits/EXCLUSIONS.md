# Dataset exclusions

Exclude **108 of 600 cases (18.0%)**: **43 task/metadata issues** and **65 grading defects**. The remaining **492 cases are 381 train / 111 test**. Task requirements, fixture metadata, and grader implementations establish these findings; a baseline failure is not needed to justify a correction.

- **Task/metadata issues:** required information is missing, or the supplied instructions conflict.
- **Grading defects:** checks reject a valid result, require an unstated output format, or fail to verify required work.

Each excluded case has one primary bucket. Keep cases that can be addressed by fixing tools or exposing existing data. Exclude cases that require correcting the task, adding missing task information, or fixing the grader. The number of similar training examples is not itself an exclusion reason.

## Split selection

The source split files contain 450 train and 150 test cases, assigned using seed 0 and task-family stratification within each domain. `load_split()` applies `excluded_cases.txt` to both splits, preserving case order and split membership.

The standard uploader selects the first six eligible train and three test cases per domain: **36 train / 18 test**. Larger uploads use the same filtered splits.

`make_splits` generates the unfiltered source split files; exclusions are applied at load time. See the [split README](README.md) for generation instructions and the held-out evaluation policy.
